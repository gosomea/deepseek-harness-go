# fs

## 概述

`fs` 的问题不是「怎么读写文件」，而是**「拿到的路径是否允许执行」**。

每个方法接收的路径都先经工作区规则解析，所以「工具无法触及世界之外」是接口的性质，而不是每个调用点各自的义务。写入还带一个可选的前置条件：调用方可以引用读取时的修改时间，若已变化就报**冲突**而不是覆盖。

## 职责

- **定义访问模式**：`read-only` 与 `workspace-write`，写权限在构造时确定而非逐次询问。
- **定义写入请求**：目标路径、内容、可选期望修改时间、是否创建。
- **定义读取上限**：单次读取有上限，一个巨大文件不会耗尽内存。
- **区分失败**：未找到、冲突、超限、非法值各有错误值。

## 使用

下面这个片段演示条件写入：把读取时看到的修改时间带回去，若期间有人改过就报冲突而不是覆盖。

```go fragment
result, err := service.Read(ctx, "notes/a.txt")
if err != nil {
	return err
}
// 把读到的修改时间带回去：期间有人改过就报冲突，而不是覆盖。
if _, err := service.Write(ctx, fs.WriteRequest{
	Path: "notes/a.txt", Content: []byte("new"), ExpectedModified: &result.Modified,
}); err != nil {
	return err
}
```

## 理解实现

**冲突检测为什么重要。** 读取与写入之间可能有人改了文件。条件写入把「读取时看到的状态」变成一次乐观锁：不匹配就报 `ErrConflict`，且**在触碰文件之前**报——所以另一个人的编辑不会被截断。

**创建为什么是独立的语义。** `Create` 用 `O_EXCL`，两次创建不能都成功，因此「创建」不会静默变成「替换」。

**读取上限为什么在读取之前检查。** 先 `Stat` 再比对上限，超出就直接拒绝，而不是先把字节读进内存再发现太大。

## 限制

- **只定义接口**：本包没有实现。
- **不定义并发协议**：冲突检测是乐观的，不是锁。
- **无目录递归删除**：删除单个文件的语义由 Provider 决定。

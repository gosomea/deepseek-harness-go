# 阶段实施索引

## 怎样使用这些方案

M0–M12 已拆成 81 个实现与学习切片。它们是待实施范围；目前只有 [M0 的 plan.json](../plan.json) 是执行契约。其他阶段在进入前将当前切片的具体文件、检查与必要 gate 登记为子计划，不用未来不存在的包和命令伪装成已经可执行的门禁。

总体选择由[总方案](../plans.md)维护，全域范围由[能力表](../capabilities.md)维护，读者主题由[学习地图](../../../learning/index.md)维护。阶段页负责实现顺序、文件归属、实验与阶段退出条件。事实变更首先修改所属页，再更新入口。

## 从细化方案进入执行

1. 读取前驱实际证据与当前工作树；历史报告和本页编号不自动解锁后继。
2. 为将开始的阶段建立 `docs/10-plans/<stage-topic>/plan.json`，沿用现有 M0 时通过 revise 变更。把切片关联到复刻、学习两个目标。
3. 将预计目录展开为具体 inputs/outputs 文件；writes 限定本阶段所有权。核对检查实际读取的配置、脚本、源码和 fixture。
4. 把必要前驱定义为 gate，并在 depends_on 中建立路径。跨计划交接不能只写“G4 已通过”：先固定前驱提交和证据摘要，在子计划入口验证仍然成立，再由本计划 gate 解锁。
5. 对尚未存在的 checker，先实施并以通过／拒绝样例验收；随后把真实命令登记进契约。禁止使用永远返回成功的占位检查。
6. validate 后领取、start、实现、verify、语义评审、render/export；只有实际通过的 evidence 能改变执行状态。

每阶段可以分多次提交。优先顺序是契约与失败用例、最小实现、学习实验、集成验收；同一个可发布切片必须同时具备实现与学习交付。当前默认串行执行，公共接口尽量先冻结再接 Provider。

## 文件所有权与共享契约

各阶段列出的路径是预计归属，未实现时保持代码文字，不建立空包。每个新 Go 包遵守[开发规则](../../../../AGENTS.md)和[文档规范](../../../documentation.md)：分类 README、包／公开注释、行为参考、源码对应、完整程序和测试共同交付。

类型与接口保持单一所有者：`llm` 管消息及模型契约，`session` 管权威日志，`agent` 管公共句柄，`agentloop` 管默认驱动。本地、远程和 tRPC Provider 依赖接口，核心包不反向依赖提供方。阶段改变共享契约时，先列所有实际消费者再验证，不以“局部改动”为由跳过受影响路径。

上游产物若会被后继修改，使用阶段基线、不可变证据和集成复验；必要时保留独立 worktree。旧证据继续证明旧提交，不能长期当作当前通过。导出不得覆盖历史 run，状态始终由 CLI 生成。

## 实现与学习共同验收

每个行为条目都关联：固定 TS 来源、Go 实现／测试、概念说明、可运行实验、失败恢复和显式差异。阶段页中的实验是设计要求；未来笔记按[模板](../../../learning/note-template.md)写成读者可复制的操作，完整 Go 程序进入文档门禁。

现有 `make check` 是阶段基础门禁。新增包时同步扩展格式、覆盖、API／注释与示例检查；模型、协议、UI、平台、兼容和发布各有专用门禁，不能由基础门禁替代。不得降低阈值或把缺失包、零测试、未运行的外部服务检查解释为通过。

语义评审使用真实 subject，覆盖复刻和学习目标；独立性如实记录。每阶段导出参考 SHA、提交、工具链、环境、命令、结果、差异与未验证范围。模型／远程服务 smoke、平台特性和发行验证单列，确定性必要检查使用 fake、可控时钟、临时目录与回环服务。

## 索引文件与规划校验

[milestones.json](milestones.json)只保存阶段文档、基础依赖、切片 ID、学习主题与固定源码路径，供结构核对。它没有执行状态，不由 plan.py 领取；实际状态查各阶段执行契约。

修改阶段时同步更新该索引，并核对：M0–M12 恰好各一份、切片 ID 唯一、依赖无环、文档和源码路径存在、总方案与细化入口一致。检查这些条件只能说明规划完整性，不能证明功能已经实现。

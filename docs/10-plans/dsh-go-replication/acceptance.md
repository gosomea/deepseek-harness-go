# 复刻与学习的共同验收

## 状态与事实归属

本页定义未来阶段的验收设计，不代表这些检查已经接入。当前可执行门禁仍由[测试说明](../../testing.md)维护。行为 fixture、差分运行器、全模块覆盖检查和学习关联检查需要在相应阶段实现，并先用通过与拒绝样例证明检查有效。

来源清单回答“有哪些部分”，能力表回答“何时处理”，逐行为账本回答“复刻到了什么程度”。不使用包个数、文档页数或总测试覆盖率代替语义覆盖。

## 行为账本

M0 从 Cordis 开始，后续每个领域建立自己的账本。每条至少包含以下字段；可以先用 Markdown 表维护，规模增长后再生成目录和机器校验。

| 字段 | 要记录什么 |
| --- | --- |
| ID 与场景 | 稳定领域 ID，例如 `cordis.dependency-loss`；一个可观察行为 |
| 来源 | 固定提交、TS 符号、参考测试或文档；有冲突时以该版本源码和可复现场景核对 |
| 契约 | 前置状态、输入、输出、状态变化、错误、取消、并发和资源释放 |
| Go 入口 | 实现符号；未实现时写预计归属，并标明规划 |
| 对应层次 | 概念、行为、格式／协议兼容或 Go 适配，可多选 |
| 自动证据 | Go 测试名／fixture；有差分时增加 TS runner、环境和 trace 归一化规则 |
| 学习证据 | 概念笔记、可运行实验、预测题与答案解释 |
| 差异 | 差异理由、影响、是否阻塞下游、后续阶段或决定 |
| 状态 | 未审计、已定义、已实现待验、已验证、显式适配、延后；附证据版本 |

“显式适配”必须有测试与评审，不能把未实现改名后计入等价覆盖。每次报告同时给出基线总条目、已验证等价、已验证适配、未验与延后数；无证据的条目不得进入已验证分子。新增或拆分条目要保留 ID 谱系，防止改变分母制造进度。

## 如何验证 TS 与 Go 的对应

优先复用参考实现中的场景语义；测试代码与 fixture 的引用记录来源和许可证。两侧运行器要吃同一份输入，分别产生可观察 trace，再比较约定的状态和结果。不得把 Go 当前输出自动录成期望并据此称为复刻。

只归一化 ID、绝对路径、时钟等明确非语义字段。并发行为用 happens-before 约束与屏障验证，不强行比较无承诺的总顺序；不能删除取消、释放顺序、错误或 stream 边界来让结果相同。Go 的真实 goroutine 竞态另由 race 与针对性测试证明。

差分运行器优先使用固定版本的只读参考或独立临时 checkout，不要求贡献者拥有作者本机路径。Node 工具链与 Go 运行时依赖分开；Cordis 保持当前零第三方运行时依赖，未来新增 Go 依赖须有必要性与许可记录。

无法运行 TS 的环境可运行经过独立核对的 golden fixture，但必须记录来源、提取方法与 TS 运行状态，不能称为现场双实现差分。真实模型请求、联网 MCP、桌面打包和 OS 沙箱分别属于有环境条件的检查；缺失环境是未验证或阻塞，不是通过。

## 每阶段共同门禁

| 门禁 | 必需证据 | 拒绝条件 |
| --- | --- | --- |
| 范围与来源 | 行为 ID、固定源码、差异与受影响消费者 | 来源漂移、没有归属、声称了未验兼容性 |
| Go 工程 | 当前 `make check`；新包同步扩展检查范围 | 格式、vet、race、行为、文档或编译失败 |
| 行为对应 | 成功与关键失败 fixture；生命周期与取消断言 | 仅验证 happy path；错误被吞；资源没有所有者 |
| 学习交付 | 从 Go 前置知识进入的笔记、完整程序、预期输出、预测与故障实验 | 只有符号对照表；读者必须先读全套 TS；复制命令无法运行 |
| 文档一致 | README、公开注释、当前参考、来源映射和索引 | 未来 API 被写成当前行为；重复事实不一致；失效链接 |
| 语义评审 | 对应 subject 的评审覆盖复刻与学习目标 | 测试通过但承诺与实现不符，或留下未解决的阻断问题 |
| 集成与发布 | 集成提交的本地结果、独立的 CI 与发布记录 | 用别的提交／平台通过替代当前结果；仅有历史报告 |

现有 90% 下限只适用于 Cordis 的 Go 语句覆盖，不是 DSH 的每文件 100% 规则。新领域在实施计划中先确定并接入适合该领域的覆盖与行为要求；不得不加选择器就声称已经受门禁保护，也不得为失败降低已约定标准。

## 高价值场景

| 领域 | 首批必须包含的场景 |
| --- | --- |
| Cordis | 注册消费者后补 Provider；Provider 失效；多级消费者先清理；启动中取消；清理错误仍继续；旧激活结果不发布 |
| Loader | 未知名称；同 ID 更新；非法配置；禁用与重新启用；一项失败与兄弟条目；重载后资源数量 |
| Session | 重放一致；序号间隙；未知事件政策；损坏尾部；只读不写入；未来版本与双写者拒绝 |
| LLM | 任意分块边界；分片工具 JSON；正文与 reasoning；终止／错误／取消；usage 缺失；请求重试后的 attempt |
| Tools | 参数错误；拒绝跳过工具体；取消；panic／错误归一；唯一权威结果；并发结果与日志顺序 |
| Agent Loop | 无工具结束；多步骤；零 step 轮次；排队与 steering；创建失败回滚；关闭／取消／恢复 |
| 本机能力 | workspace 边界、符号链接与路径；审批无应答；进程树终止；有界输出；文件冲突和权限 |
| 上下文与长任务 | 模型可见日志不变量；压缩失败；截断与 spill；子代理隔离；持久任务恢复与重复执行 |
| 协议与客户端 | 版本不匹配；断线重放；慢消费者；取消传播；跨会话授权；Host 状态与客户端投影一致 |

采用内存 fake、可控时钟、通道屏障、临时目录和回环服务。避免真实 sleep、固定端口、宿主全局环境与联网 API 参与必要确定性门禁。测试要验证契约，避免逐行镜像实现。

## tRPC 模型适配器门禁

模型层选型由[总方案](plans.md#模型接入选型trpc-agent-go)维护。以下门禁在 M4 接入 `plugins/llmtrpc` 时建立，并写入该阶段执行契约；当前 M0 契约不因此增加模型调用任务。

| 验证项 | 必需结果 |
| --- | --- |
| 依赖与边界 | 锁定具体模块版本与源码，核对最低 Go 版本、间接依赖和许可；导入检查拒绝核心包依赖 tRPC 类型或 Agent/Runner |
| 请求转换 | 消息角色、内容顺序、模型路由、参数、工具 schema 与 tool-call ID 保持约定；不支持项明确拒绝 |
| 流与组装 | 正文、reasoning、分片工具参数、多个工具调用、终止原因、usage 含零值与缺失均有回环 fixture；按契约验证 delta 边界及组装结果 |
| 扩展与回放 | DSH 基线需要的供应商扩展和 replay 信息有保留路径；能力缺口有明确诊断，禁止静默丢弃 |
| 错误与取消 | 同时覆盖调用建立失败和响应流内错误；中途取消、慢消费者、提前停止读取均关闭资源并释放 goroutine |
| 重试与结算 | 核对底层重试设置，避免两层重试；每次受管理的模型 attempt 可观察，流错误不伪装成正常结束 |
| 生命周期 | Cordis 卸载停止在途调用并完成清理；适配器不执行工具、不写 Session，不引入第二套运行时状态 |
| 学习实验 | 同一场景可经 fake 与 tRPC 回环 Provider 运行；笔记逐项解释 DSH、Go、tRPC 三层转换及差异 |

必要检查使用固定响应的回环 HTTP 服务，无需密钥或外网；上游字段变化通过固定版本 fixture 和拒绝样例检测。M7 才增加凭据／真实端点接入检查，联网 smoke 的通过、失败或未运行单独报告。每次升级 tRPC 依赖都重跑受影响的适配器契约与集成测试；不能因为库声称兼容 OpenAI 就推断兼容全部 DSH 扩展。

## 学习验收怎样做

审阅者从干净 checkout 按学习顺序执行：先预测输出，再运行完整程序，改一个条件观察失败，最后定位两侧实现并解释差异。每篇完成后能回答三个问题：这个机制解决什么问题，谁拥有并释放资源，为什么选择这种 Go 表达。

代码／链接工具无法判断读者是否理解，所以保留人工语义评审。当前默认作者完成单独审阅并记录 `independent: false`；获得独立评审时如实记录评审者、范围与结果。自动检查通过和学习效果不是同一个证据。

## 证据生命周期

每个计划固定输入与输出，CLI 导出到新的 `validation/<run-id>`。同时记录工具版本、操作系统、提交、参考 SHA、实际命令和未运行的可选检查。计划状态由 CLI 生成，任何 pending、failed、stale 或缺少评审都不能解释为通过。

长期演进使用阶段计划；下阶段不能悄悄覆盖上阶段仍被依赖的可变输出。需要并行或修改上游文件时，保留独立工作树与不可变交付，再在集成节点重验。项目当前可用性由当前提交的检查说明，历史导出证明历史状态。

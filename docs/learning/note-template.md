# 概念对应与学习笔记模板

## 使用方法

这是写作者模板，不是一个已实现模块的教程。新主题放入所属模块的 `docs/<domain>/`，由[学习地图](index.md)链接；包 README 为消费者提供入口。已有概念继续在原归属页维护。下列各节填写具体内容，无关项目可以解释适用边界，不能留下空标题或“后面补”。

## 读完要解决的问题

以读者能观察的问题开篇，例如：“Provider 移除后，为什么拿着接口值的 Consumer 还必须停止？”列出所需 Go 知识、关联行为 ID、当前实现范围和可运行入口。用一句话说明完成实验后能做什么，区分源码已实现和本文仅讨论的设计。

## 从熟悉的 Go 写法出发

先描述普通 Go 做法及其边界，例如构造函数注入能确定初始依赖，但不能自行感知运行中服务失效。随后引入解决这个问题的 DSH 概念。每个新术语第一次出现时给出含义；类比之后说明哪里不等价。

## 最小实验

写明准备条件、仓库根目录、完整命令、预期 stdout、退出状态和观察重点。命令必须在当前仓库中可运行。手写完整 Go 程序使用 `go runnable=<id>`，同页配对 `text output=<id>`；引用现有示例输出使用 `text output-file=<path>`，规则见[文档规范](../documentation.md#代码与输出)。

先给一个最小成功场景，再逐步增加一个因素。每一步都能独立复制执行，不能要求读者拼接前几页的变量。需要密钥或网络的内容放在独立小节，并先提供不依赖它们的 fake 实验。

## 先预测，再观察

提供一项可控改变，让读者先写出预期。例如移除 Provider、取消正在进行的请求、损坏 fixture 尾部或拒绝工具授权。随后给出观测方法、结果与解释，以及如何恢复到正常场景。练习答案必须能从实现或测试追溯，不使用无法验证的主观问答。

## 两种实现怎样对应

| 项目 | 必须填写的内容 |
| --- | --- |
| DSH 概念 | 角色、触发条件、它解决的问题 |
| TypeScript 入口 | 固定提交的公开源码链接、符号和相关参考测试 |
| Go 入口 | 当前仓库的相对链接、符号与对应测试 |
| 保持的行为 | 输入、输出、状态变化与失败语义 |
| Go 表达 | 接口、结构体、显式注册、context、通道等选择及理由 |
| 不等价边界 | 差异、未实现项、版本／平台限制与下游影响 |

如使用 TS 片段，只解释当前实验需要的语法；不要把完整 TypeScript 教程作为前置条件。签名目录从源码生成，概念笔记负责“为什么”和“怎样验证”。

## 一次操作的时序与所有权

用步骤或小型时序图说明谁调用谁、谁持有状态、何时发布结果、取消到哪里传播、谁释放什么。涉及 goroutine 时说明共享状态与等待方式；涉及存储时说明 append、可见、flush、提交和恢复的区别。图只画当前实验需要的参与者。

## 失败与定位

列出实验会遇到的两到三个关键失败：症状、原因、诊断入口和恢复操作。区分预期等待、无效输入、执行失败与释放失败。语义详解链接到所属参考页；必要的使用限制在命令附近直接说明。

## 回到源码与下一步

给出建议的函数阅读顺序、关联行为 ID、对应测试名和下一篇笔记。读者应能回答“机制解决什么问题”“谁拥有资源”“Go 与 DSH 的差异在哪里”。运行证据放进所属计划的 validation，学习正文不复制验收日志。

## 写作者交付检查

- 实现、源码映射、文档示例、行为测试共同对应同一组行为 ID。
- 完整程序通过当前文档程序门禁；片段如实标记，不宣称已独立编译。
- 当前能力与未来规划分开；未创建的路径用代码文字说明，不写失效链接。
- 事实保留一处所有者；学习地图、模块 README 与参考页能够互相导航。
- 语义审阅执行一次“预测→实验→失败→定位源码”，并在计划中记录真实结果。

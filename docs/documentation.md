# Go 仓库文档规范

## 概述

本规范把 DSH 的读者优先、逐步学习、事实归属与可执行示例要求应用到 Go 仓库。README 根据用途选择结构，教程提供操作与可观察结果，参考说明当前行为、失败和所有权。格式检查能发现缺失或过时内容，准确性与教学顺序仍需代码评审。

## 读者与文档归属

第一次学习的读者已经掌握 Go 基础，但不要求了解 Cordis 或 TypeScript。教程在引入 Inject、Fiber、激活和 Scope 前建立相应概念。每一步写明准备条件、完整操作、成功结果与可能的失败；深入规则链接到参考页。

| 文档 | 维护的事实 |
| --- | --- |
| 项目首页、文档索引 | 项目能力、启动入口、学习与查阅路径 |
| 包 README | 消费者如何使用此包、主要失败与限制、扩展方式 |
| Cordis 教程与概念对照 | Go 知识如何连接到 Cordis，逐步可运行的程序 |
| 生命周期、服务、事件参考 | 当前时序、错误、并发条件与资源所有权 |
| 生成 API | 源码导出与公开注释；修改源码后重新生成 |
| 架构 | 当前组合与依赖方向；包内部细节链接到包文档 |
| 路线图与计划 | 后续范围、决策、执行条件和验收证据 |
| 学习地图 | Go 前置知识、主题依赖、当前可学与未来主题的入口 |

同一解释在其归属页维护，其他页面链接到它。为保证安全使用，简短的所有权、失败或等待规则可以在操作处再次说明。教学程序可以逐步演进；每个完整版本均独立检查，不依赖读者拼接未声明变量。

复刻切片同时交付概念对应与学习实验。新主题按[学习笔记模板](learning/note-template.md)组织，在模块文档中维护解释；[学习地图](learning/index.md)只负责导航。每项承诺关联固定 DSH 来源、Go 实现、行为测试、可观察实验和差异，验收方法见[共同验收标准](10-plans/dsh-go-replication/acceptance.md)。

## README 类型与模板

每份维护中的 README 以 `description` 和 `kind` 开头。两者使用单行双引号字符串；值中的引号或反斜杠需要转义。这是工具支持的 YAML 子集，当前不使用其他字段或多行值。

```text
---
description: "读者可以做什么，主要结果或使用条件。"
kind: "package-library"
---
```

| 类型 | 所在位置与识别条件 | 必需 H2 章节，按顺序 |
| --- | --- | --- |
| project-overview | 仓库根 README | 概述、目录、快速开始、学习路径、开发与验证、授权 |
| documentation-index | docs/README | 概述、目录、学习路径、查阅参考、开发与验收 |
| package-library | 普通 Go 包 | 概述、目录、职责、使用、理解实现、进一步阅读、验证、限制 |
| command-example | examples 下的 package main | 概述、目录、职责、使用、验证、限制 |
| command-tool | 其他 package main | 概述、目录、职责、使用、验证、限制 |

库、示例与工具分别使用[库模板](templates/package-library.md)、[示例模板](templates/command-example.md)、[工具模板](templates/command-tool.md)。首页与索引的完整结构由上表和实际页面维护。每个必需章节有解释性正文，不能仅有标题、HTML 注释或 TODO；标题不重复，目录链接指向实际章节。生成和冻结的验证历史不套用这些模板。

这些模板适配 Go 包用途。通用库没有模型请求时，可以在限制中说明而不添加空的模型体验章节。未来包生成模型可见内容时，必须记录内容、条件、token 和缓存影响。npm profile 安装、双语配对与网站投影尚未纳入本仓库；增加相应能力时补充其规范与检查，不声称本仓库已经运行 DSH 的 TypeScript 门禁。

## 代码与输出

每个手写 Go 代码块明确分类。完整程序使用 `go runnable=<id>`，同页必须有 `text output=<id>`，id 使用小写字母、数字和连字符且不重复。空 stdout 用空输出块表示。检查器在仓库 module 中编译程序，再运行可执行文件，逐字比较 stdout；编译和运行合计最多 30 秒，非零退出或超时失败。

```text
代码块头：go runnable=hello
内容：完整的 package main，包含 imports 和 main。

输出块头：text output=hello
内容：程序预期 stdout，包含末尾换行。
```

上下文片段使用 `go fragment`，正文说明哪些变量已存在，并链接完整程序或接口参考。片段不作为独立程序执行，也不宣称已经完整类型检查；公开 API 的声明只允许出现在唯一的新鲜度检查所有者 `docs/cordis/api.md`。

文档复述已有输出时，用 `text output-file=<仓库相对路径>` 指向输出所有者。检查器拒绝缺失、逃逸或内容不符的文件。代码块可用反引号或波浪线围栏，结束符必须完整闭合；代码块中的 Markdown 标题不算 README 章节。

## 写作与评审

概述用一个短段落说明读者能做什么、所需知识或使用条件，以及最重要的限制。先写可执行操作，再给开发者细节；较长的内部说明放入 details，章节标题保持可见。段落使用编辑器软换行，文件中每段占一个物理行；术语保持一致。

当前参考写已实现的行为，未来模块放到路线图，执行历史放到计划与验证记录。保留错误、取消、等待、释放顺序和并发限制；删改篇幅时不丢失条件或例外。链接使用仓库相对路径，外部参考使用读者可访问的地址；固定参考源码的版本信息由源码对应表维护。

评审先按新读者路径运行命令，再对照实现核对结果。无效配置、启动失败、服务缺失和卸载重叠不能被当作同一类情况。元数据与章节非空不能证明语义正确，正文仍需审阅。

## 检查入口

`make docs` 检查 README 结构、公开注释、链接、代码块分类和 API 新鲜度；`make doc-examples` 编译并执行完整文档程序。阶段交付执行 `make check`，包括这两个入口和检查器的拒绝样例，具体要求见[测试说明](testing.md)。修改规则时增加通过与拒绝样例；生成 API 通过 `make api` 更新。

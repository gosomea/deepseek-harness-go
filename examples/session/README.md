# examples/session

## 概述

这个程序不调用模型、不读磁盘：它用 Go 代码写出一份九条事件的会话日志，然后打印三件事——每条事件是否可能成为模型消息、从日志派生出的模型历史、以及在装上内容投影前后的差异。读它能让 [投影笔记](../../docs/session/projection.md) 里的每一步都有一个可运行、可对照的实体。

## 职责

演示 M3 的四条核心行为：

1. **日志变长，历史不变**：轮次边界、工具调用与一次失败的模型尝试都进入日志，却不进入 surface。
2. **空消息占位但不产出**：空 system 与空 assistant 消息占据 surface 节点，却不产生 wire 消息。
3. **投影改写而不增删**：装上一个把目标消息内容换成占位文本的解释器后，历史内容变了，日志形状没变。
4. **校验先于提交**：未知必需事件、缺少 `surfaceOp` 的消息与越界替换都被拒绝，日志保持原样。

它不负责提供真实模型、持久化或工具执行——那些属后续阶段。

## 使用

```sh
go run ./examples/session
```

输出逐字保存在 [expected.txt](expected.txt)，并由 `TestDemoMatchesDocumentedOutput` 比对。程序的时钟是固定的，所以两次运行输出相同。

## 验证

```sh
go test -race -count=1 ./examples/session
```

三条测试分别固定：输出与 `expected.txt` 一致、两次运行可复现、以及九条事件／四个 surface 节点／四次拒绝这些关键计数。

## 限制

- 日志是**内存**的：程序结束即消失，没有磁盘格式。
- 投影是一个**等价替身**，不是真实的图片 offload 实现——附件服务属后续阶段。
- 模型是假的：本程序不联网、不需要密钥。
- 它只演示 M3 范围；流、assembler、工具执行与 Agent 轮次属 M4／M5。

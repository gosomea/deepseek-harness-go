# examples/cli

## 概述

这个程序不联网、不需要密钥：它在**自己的临时目录**里建一个执行世界，然后按顺序演示四件事——读取文件、**被拒绝的写入（文件不变）**、被允许的写入、只读策略下被拒绝的命令——最后把一次轮次记入会话日志并**重开**，证明历史确实留下了。

它演示的是顺序，不是功能清单：**策略必须发生在副作用之前**。因此输出里最关键的两行是「拒绝之后文件未变」与「随后允许的写入才改变文件」。

## 职责

1. **拒绝先于副作用**：第一次编辑走 `deny` 政策，工具返回 `ErrPolicyDenied`，程序随即断言文件内容**仍是原文**。
2. **允许才生效**：同一个调用换成 `allowed-once` 应答者后成功，并打印写入字节数与新内容。
3. **不能隐式降级隔离**：`read-only` 策略下运行命令被拒绝，而不是"为了跑通"去掉限制。
4. **重开一致**：会话日志写入四个事件（轮次边界 + 两条消息），重开后派生出的历史与写入时相同。
5. **只写自己的临时目录**：程序结束时删除，测试断言没有残留。

## 使用

```sh
go run ./examples/cli
```

输出逐字保存在 [expected.txt](expected.txt)，由 `TestCLIDemoMatchesDocumentedOutput` 比对。程序使用固定时钟与脚本化数据，因此两次运行输出相同。

## 验证

```sh
go test -count=1 ./examples/cli/...
go run ./examples/cli
```

测试逐字比对快照、两次运行的一致性，断言「拒绝在允许之前」这一顺序，并检查示例不在系统临时目录留下 `cli-e2e-*` 残留。

## 限制

- **没有真实模型**：端点是脚本化的；真实端点接线见 [plugins/llmtrpc](../../plugins/llmtrpc/README.md)，联网 smoke 单列且缺密钥记为未验证。
- **审批是脚本化的**：`deny` 与 `AllowedOnce` 应答者代表两种结果，没有交互界面。
- **不覆盖 Windows**：进程与路径行为只在本机（macOS）验证过。
- **命令被拒绝而非执行**：示例演示拒绝路径，不演示真实命令输出。
